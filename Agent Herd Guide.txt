A few notes before we get started:

This guide covers setting up Travisse's preem af Cyberpunk Red Foundry app using Laravel Herd instead of Docker/DDEV. By the end of this, you'll have a working web app that is accessible by both the host PC as well as other devices on your home network like phones, tablets, laptops, ect. Getting it to talk to the bridge module in Foundry is pretty well documented already, so I'm not covering that, but if need be I will gladly update this guide to include those steps as well.

This all prolly looks like a lot, and it kinda is, but once its set up correctly, its just a few clicks and keystrokes to boot up Herd, fire up reverb and Foundry, then its go time! A simple windows CLI batch script can do all that in one click too! I even ended up making a QR code for my players to scan and quickly get to the app when they get here. 

This was done on a Windows 11 PC. I cannot help with Mac, but Herd does offer an installer for MacOS. 

This guide assumes you do not have any dependancies installed already and that you have some familiarity with tinkering around with command line interface instructions. Even if you dont though, I've tried to break it down so that its not too hard to follow as long as you can google or ask questions when stuck. I'm no pro but I will help where I can. Honestly if you can work out how to do any advanced stuff with Foundry, you can probably figure this out, too. :D

These steps will get you up and running for a locally hosted in-person session, where the players use a phone, laptop, tablet, or w/e to control their character. I believe you can use the same platform to make your instance accessible from outside your home network but I can't speak to what those additional steps look like. 

In order to let other devices connect to your running app, they will need to be able to connect to your host PC's local IP address directly. I've laid out how to do that later on in this document but to make your life easier, you really wanna set up your host machine with a set STATIC IP address. Google it, there's a hundred guides out there and its not too complicated. You wanna do this otherwise you'll potentially be editing your files all the time when your router gives you a new IP.

This setup doesnt connect to the greater internet, so you cant send password reset emails. (or at least I dont know how. my players accounts are just nonsense emails and passwords they cannot forget)

If I say Terminal, I mean either Command Prompt or Powershell will work. If I call out Powershell, it has to be Powershell. 

Lastly, while I am no expert on any of this, and there might be an easier way to do it, I've gone through my own instructions twice to make sure it works. Its been a ton of research on how any of this works and then moving it from one platform to another, but writing this all out as I went ended up simplifying the process a lot. This app was just too perfect for my use case to surrender, and I hope this helps you get it online too!

With all that out of the way, LETS DO THIS.

----------------------------------------------------------------------------------------------------------------------------------------------------------------------


1.) Download and install Laravel Herd + any dependencies it asks for. 
- Herd does basically what Docker does for creating a local live dev environment, except it does so as a native windows application. No complicated containers or wonky networking issues. Since Travisse's work is built with Laravel we can spin it up in Herd without too much pain.
- The free version of Herd will work just fine.:  
          https://herd.laravel.com/docs/windows/getting-started/installation


2.) Clone repository. 
- Open up a Terminal window and navigate it to wherever you want the root folder for the app to live on the host PC. Then run this command to grab the current build of the app:
          git clone https://gitlab.com/surrealtech/cyberpunk-red-agent
- It will stick the folder "cyberpunk-red-agent" inside whatever directory your command prompt window is currently pointing at. Make sure its in a good permeant home that is accessible easily, or just make a shortcut to it wherever you want. 

>>>>>>> The cyberpunk-red-agent folder will be referred to simply as "root folder" from here on out. <<<<<<<

- Go inside your root folder we just cloned and locate the file ".env.ddev". Flatline it. Replace it with the file ".env" that I have included for you. 
- Keep this folder handy. We'll be back soon. 


3.) Setup your site in Herd. 
- If you didn't already, open up Laravel Herd. If this is the first time booting it up, it may ask to install a couple of things. Do that. Skip Pro. 
- Once you are looking at Herd's dashboard go to "Sites" on the left and create one. We want to "Link existing project" and point it at our root folder.
- Leave everything as-is on the path and name. (actually I think you can name it w/e you want as long as its reflected in your .env, but I haven't tried it myself. Leave HTTPS off as well. 
- This step builds some server files we need, but the site won't work just yet. You can go ahead and minimize Herd. 


4.) Install dependencies and generate an app key. 
4a. Install Nodejs. 
- You might already have this if you run a headless Foundry like I do, if not install this too. It's free and facilitates javascript and such in the background.
          https://nodejs.org/en/download

4b. Install Composer dependencies & frontend packages.
- If you're still in a Terminal from previous steps, close it out and navigate a new Terminal to your root folder. This makes sure it'll be updated with any new system paths from what we've done so far. 
- Run the following prompts one at a time. They might take a sec: 
          composer install
          npm install

4c. Generate an app key.
- Still in the same Terminal, run the following prompt: 
          php artisan key:generate
- This will create your unique key laravel needs for encryption and automatically inserts it into your .env file for you.
- If that fails you probably did not install the dependencies first or replace the .env file correctly back in step 2. 


5.) Edit your .env file. 
- I strongly suggest using Notepad++ for this for many reasons. Its free and an excellent lightweight tool for editing code blocks cleanly without mangling any lines. 
- The .env I've supplied just needs the local IP address of your host machine. If you do not know how to find this, simply open a terminal and run ipconfig from anywhere. Look for the line IPv4 Address. That's what we are after. 
- Now inside your .env file, find the following lines and replace the "X" in the IP address with the correct last digit(s) of your host PC's IP in 3 places:
   - Line 6:   APP_URL=
   - Line 27:  SANCTUM_STATEFUL_DOMAINS= (In both spots on this line)
   - Line 39:  VITE_REVERB_HOST=
- Save the file.


6.) Setup Database.
- This step will set up a simple database for your logins and whatnot. 
- You'll need to open up a Powershell window for this one. Navigate it to your root folder and run the following two commands one at a time: 
          New-Item -ItemType File -Path "database\database.sqlite" -Force
          php artisan migrate --seed


7.) Compile the front end.
 - Tired of looking at Terminals yet? Too bad! We're getting there though! Run this in your root folder.
          npm run build


8.) Start reverb server. 
- Copy this next command down somewhere cause you'll need it every time you wanna spin up the app. Its basically the middle-man between the app's backend and the user interface. It makes everything sync up beautifully and facilitates that "live" environment for your users.
          php artisan reverb:start --host=0.0.0.0 --port=8080

- LEAVE THIS WINDOW OPEN. It might look like its not doing anything, but unless it throws an error, its quitly doing its job as long as you do not close this window (or end the process with cntrl+c).


9.) Make sure all this nonsense worked before we move on.
- If you followed these steps exactly Herd should default your apps url to cyberpunk-red-agent.test <--- Open this up in a web browser on the host PC and pray you see that login screen! I bet you will, and if you don't, It's probably a simple fix we can work out.
- To make sure everything is talking to each other, go ahead and make a throwaway account to log in. You don't even need to use an actual email address, but it does need to be in an email format, like test@test. If you get a 419, 500, or anything else, something got borked in the setup. It could be a large number of things, so carefully retrace your steps first and do a little investigating, then if ya need to reach out and see if we can sort it. Opening up your browsers developer tools (F12 usually) and checking the console for errors is a good place to start. 
- If we did it right you should be looking at the dashboard for the stand-in netrunner character. Victory!
- We still need to setup for other local devices to be able to connect, but the worst part is over. 


10.) Setup LAN access for local devices.
- Ok, so your app is running at cyberpunk-red-agent.test, and that's cool, except since that's a bs URL, no device except the host PC can know what that actually is. We've set your host's local IP in our .env file, but we need to update Herd about that with a couple of steps.
- By default, Nginx (Herd's web server) is just looking at your own machine's loopback address.  What we are gonna do is tell Herd to listen to LAN traffic directed at your host machine's IP and kick that where it needs to go.  

- Open up a file explorer window and navigate to:  C:\Users\YOUR_USERNAME\.config\herd\config\nginx\
- Go into herd.config (using Notepad++) and edit the following line near the top: 
          listen 127.0.0.1:80 default_server;
     - To instead read: 
           listen 0.0.0.0:80 default_server;

- Just a line or two below that you will see the line starting with "root" that probably just shows "/" for a value.
     - replace the line with this exactly: 
          root "YOUR_ROOT_FOLDER_DIRECTORY/public";  <--- Note this must use FORWARD slashes. If you copy/paste the directory from file explorer it will use backslashes, and you'll have problems. copy/paste is fine, just replaces those backslashes (\) with forward ones (/).
     - obviously you wanna replace all the capped text with your root folder's full directory. Wherever you stuck it way back in step 2. 
- Save the file.

- Next, using a Terminal inside your root folder, enter the following: 
          herd link YOUR_HOST_PC_IP  <--- replacing the capped text with your IP. The same one we looked up earlier for your .env file that you hopefully made static!
- That should direct Nginx, now listening to LAN traffic, to route that traffic to your Agent app. 


11.) Open up the needed ports on the host PC
Run the following command in an elevated Powershell window (as Admin) that is navigated to your root folder. Make sure its as admin or it'll throw an error.
          New-NetFirewallRule -DisplayName "Laravel LAN Access" -Direction Inbound -LocalPort 80,8080 -Protocol TCP -Action Allow


12.) I SWEAR WE ARE SO CLOSE CHOOM
- On Herd's dashboard, click "Stop all services" then start them up again. 
- Run the following 2 commands inside your Terminal thats inside your root folder to clear out the cache and apply changes we have made. 
          php artisan optimize:clear
         
- Remember that reverb process we were supposed to keep open? if that's not still running, fire it up again:
          php artisan reverb:start --host=0.0.0.0 --port=8080


AIGHT. Moment of glory. Get your phone out, make sure its on your wi-fi, click directly in your web browser's address bar and type in exactly your host IP. Nothing before or after, and dont click it from a dropdown. Tends to cause trouble or just try to google search it, which obviously isnt gonna work. 

- If everything went smoothly you should now be looking at the login screen and be able to register an account! If not, its possible a step was missed, or I might not have accounted for something on your PC that caused the setup to go awry, OR even still, maybe my instructions aren't as clear as I thought they were. Either way, I bet we can figure it out.
